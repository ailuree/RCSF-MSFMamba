# 毕设答辩 Web 应用构思文档

## 1. 目标定位

本应用不是论文网页复刻，也不是训练平台，而是一个面向答辩末尾 3 到 5 分钟展示的项目展示型 Web 应用。

核心目标有 4 个：

1. 直观说明课题到底做了什么。
2. 清楚展示“多模态遥感数据融合 + 地物分类 + 鲁棒性增强”的完整技术路线。
3. 把已有实验结果转化为更容易理解的交互式展示。
4. 让答辩老师能够一眼看到项目工作量，而不只是看到最终几个指标。

因此，这个应用的重点不是“功能很多”，而是“叙事清楚、视觉直观、信息密度高且可控”。

## 2. 面向对象与使用场景

主要面向以下场景：

- 本科毕设答辩时，PPT 最后一部分的现场展示
- 给导师或答辩老师快速演示项目内容
- 作为论文之外的工程实现补充材料

主要面向以下用户：

- 对遥感和深度学习不一定熟悉的答辩老师
- 关注“你具体做了什么、改了什么、验证了什么”的老师

因此界面要尽量避免大段论文式文字，更多使用：

- 流程图
- 模块结构图
- 指标卡片
- 预测结果对比
- 局部区域可视化
- 类别级与鲁棒性图表

## 3. 应用主题与叙事主线

建议应用主标题：

`基于深度学习的多模态遥感数据融合与地物分类一体化方法设计与实现`

建议副标题：

`以 MSFMamba 为基线，围绕融合可靠性、跨状态调制与鲁棒训练完成模型改进、实验验证与可视化分析`

整个应用建议围绕 3 条主线展开：

### 3.1 主线一：任务是什么

说明输入是什么、输出是什么、为什么要做多模态融合。

- 输入：HSI + LiDAR / Auxiliary modality
- 输出：像素级地物分类图
- 目标：提升复杂城市场景下的分类精度、类别均衡性与退化鲁棒性

### 3.2 主线二：我做了什么改进

强调你的工作不是直接使用原论文代码，而是在基线基础上做了三类增强，并完成完整实验闭环。

- Reliability Gate
- Cross-State Modulation
- Robust Training
- Full Model v1 统一整合

### 3.3 主线三：结果证明了什么

用定量结果、定性结果和鲁棒性结果共同说明：

- 完整模型综合最好
- 鲁棒训练是最稳定的核心增益来源
- 局部区域和类别级结果能够解释综合指标提升

## 5. 应用整体结构建议

建议做成单页滚动式 Web 应用，顶部导航可跳转到不同区块。

推荐信息结构如下：

### 5.1 Hero 首屏

作用：

- 一眼说明课题主题
- 迅速建立“这不是普通 PPT，而是项目系统展示”的印象

建议内容：

- 题目
- 一句话摘要
- 两个数据集名称
- 关键结果数字，例如：
  - `Houston2013 OA: 91.87%`
  - `Houston2018 small OA: 91.14%`
- 一个“开始查看项目”按钮

### 5.2 任务与输入输出区

作用：

- 让老师先理解问题定义

建议内容：

- HSI 图、辅助模态图、GT 图三联展示
- 简洁流程：
  - 输入多模态数据
  - 特征提取与融合
  - 状态空间建模
  - 输出分类图

建议配一句解释：

`本项目针对高光谱与辅助模态遥感数据，完成了从多模态输入、融合建模到像素级地物分类输出的一体化设计。`

### 5.3 方法设计区

作用：

- 这是最关键的“体现工作量”区域

建议拆成 4 张卡片：

1. Baseline: MSFMamba
2. Reliability Gate
3. Cross-State Modulation
4. Robust Training

每张卡片包含：

- 模块名称
- 结构位置
- 设计动机
- 解决的问题
- 实现层级

例如：

- Reliability Gate：位于 `FSSBlock`，用于显式重标定融合输出可靠性
- Cross-State：位于 `Fuse_SS2D`，用模态摘要调制 `dts/Bs/Cs`
- Robust Training：位于训练与评估流程，构造 degraded 分支并加入一致性约束

### 5.4 工程实现闭环区

作用：

- 直接体现“设计与实现”

建议内容：

- 数据准备
- 训练入口
- 评估入口
- 可视化入口
- 结果汇总

可做成一个工程流程图：

`数据准备 -> 训练 train.py -> 评估 eval.py -> 可视化 visualize.py -> 结果汇总 checkpoints`

这里建议加一个“工作量面板”，用数字和清单体现工程量：

- 改进模块：3 个
- 统一整合模型：1 个
- 主结果分支：5 个
- 主分析数据集：2 个
- 随机种子重复实验：3 组
- 退化评估模式：4 种
- 训练 / 评估 / 可视化脚本闭环：已完成

### 5.5 主结果对比区

作用：

- 先用最直接的数字建立可信度

建议内容：

- Houston2013 五分支主结果表
- Houston2018 small 五分支主结果表
- 指标卡片高亮：
  - Full Model v1 综合最优
  - Robust Training 单模块最强

建议表现形式：

- 表格 + 排名高亮
- 或交互式切换数据集

### 5.6 定性可视化区

作用：

- 让老师肉眼看到“具体改善在哪”

建议内容：

- 输入与标注图
- ROI 定位图
- 改进聚焦图 `fig5_3_houston2013_improvement_focus.png`
- 方法优势图 `fig5_4_houston2013_method_advantage.png`

建议加入交互：

- 点击切换 `GT / Baseline / Robust / Full Model`
- 鼠标悬停显示区域说明
- 点击按钮切换 `Global` 与 `ROI`

### 5.7 类别级与鲁棒性分析区

作用：

- 这是最适合答辩时“讲深一点”的部分

建议内容：

- `fig5_extra_houston2013_per_class_gain.png`
- `fig5_extra_houston2013_robustness.png`
- 必要时加入 `fig5_extra_houston2013_metrics_dashboard.png`

这一部分的叙事口径要与论文保持一致：

- Full Model v1 综合指标最好
- 鲁棒训练是最稳定的核心性能来源
- 类别级收益并不完全一致，但整体性能与类别均衡性提升

### 5.8 项目总结区

作用：

- 用很短的语言收束应用

建议内容：

- 我解决了什么问题
- 我做了哪些改进
- 我验证了哪些结果
- 项目最终结论是什么

建议结论口径：

- 完整方案综合性能最好
- 鲁棒训练贡献最稳定
- 结构改进提供补充增益与研究探索价值

## 6. 最适合答辩展示的功能设计

这个应用不建议做复杂后台，优先做“强展示型前端”。

建议保留以下功能：

1. 数据集切换
   - Houston2013
   - Houston2018 small

2. 方法切换
   - Baseline
   - Reliability Gate
   - Cross-State
   - Robust Training
   - Full Model v1

3. 指标视图切换
   - Overall metrics
   - Per-class gain
   - Robustness

4. 图像对比切换
   - 输入图
   - 预测图
   - ROI
   - 改进图

5. 工作量展示
   - 模块改进说明
   - 代码结构图
   - 实验闭环说明

不建议在第一版中加入的功能：

- 在线模型推理
- 后端数据库
- 用户登录
- 可编辑训练配置
- 超复杂三维遥感可视化

原因很简单：答辩场景中收益低、开发成本高、风险大。

## 7. 建议的视觉风格

应用需要体现“遥感 + 工程 + 答辩展示”三种气质，建议采用：

- 明亮底色，不要做纯黑炫技风
- 主色以深蓝、青绿、橙红为主
- 大号标题 + 大图卡片 + 清晰数据模块
- 用网格布局体现工程秩序感
- 避免花哨动画，重点做有节奏的入场动效和图表切换

建议整体风格关键词：

- 科研展示
- 工程感
- 空间数据
- 清晰而高级

## 8. 技术实现建议

建议单独建一个前端目录，例如：

`A-MyCode/web-showcase-app/`

建议技术方案：

- 前端框架：React + Vite
- 样式：Tailwind CSS
- 图表：ECharts 或 Recharts
- 静态资源：直接读取本地整理后的图片与 JSON/CSV

原因：

- 适合单页展示型应用
- 构建快，易本地运行
- 后续打包演示方便

应用应优先设计为“纯前端静态站点”。

这样有几个好处：

- 不依赖后端服务
- 本地答辩现场运行更稳
- 后续导出或部署更方便

## 9. 第一版实施范围建议

第一版不要贪大，建议只做以下 6 个区块：

1. 首屏概览
2. 任务与数据说明
3. 方法设计与改进点
4. 主结果对比
5. 定性可视化
6. 鲁棒性与类别级分析

只要这 6 个区块做好，已经足够答辩展示。

## 10. 第二版可扩展方向

如果第一版顺利，再考虑增强：

- 模型结构示意图做成可点击分层高亮
- 加入 confusion matrix 热力图
- 加入 seed 统计稳定性图
- 加入“实验时间线 / 开发里程碑”区块
- 加入“模块代码位置”折叠卡片

这些扩展更适合在第一版稳定后再追加。

## 11. 当前推荐的最终方案

综合你的论文、代码、实验结果和答辩需求，我建议我们构建的是：

`一个单页式、强展示型、纯前端的毕业设计成果展示 Web 应用`

其核心特征应为：

- 用图形化方式解释任务和方法
- 用交互式结果展示增强说服力
- 用工程闭环和模块拆解体现工作量
- 用论文一致的结论口径保证内容稳健
